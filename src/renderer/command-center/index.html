Code Graph

Model Context Protocol — project symbol graph.

About this panel

What this does

Builds a structural map of every project — files, exports, functions, classes, imports — served over MCP (Model Context Protocol). Forge and Vigil consult this graph before editing code, so the agents know which call sites a function has and which files import a module. It's how Forge avoids breaking distant callers when refactoring.

How to read it:

  • Status — ready means the graph is built and queryable; building means a rebuild is in flight; stale means files changed since the last build and a rebuild is queued.
  • Symbols / files — counts give a feel for project size; expect a few hundred symbols for a typical landing page, tens of thousands for KageOps itself.
  • Last built — the graph rebuilds on project.created and after large file changes. Manual rebuild from the action above the table.

When this matters: if Forge keeps producing changes that break unrelated callers, the graph is probably stale or missing — check status here. If it shows error, the graphify worker likely couldn't parse a new file extension; see Help → Troubleshooting.

GitHub

Personal access token and per-project repo wiring.

About this panel

What this does

Lets KageOps push commits, open PRs, and read CI status on your behalf. A Personal Access Token (PAT) with repo scope is required. Per-project mappings (github_owner / github_repo) tell Aegis where to push when a project is built — without a mapping, KageOps stays local.

How to use it:

  • Set the PAT — paste a fine-grained token here. It's stored in the OS Keychain (macOS Keychain / Windows Credential Manager / libsecret), never in plaintext.
  • Per-project mapping — attach a owner/repo to a project to enable auto-push and auto-PR for that project. Other projects stay unaffected.
  • Disable globally — set KAGEOPS_DISABLE_GIT=1 to make all git/GitHub operations no-ops. Useful for benchmarks and throwaway tests.

Recommended scopes: repo (push, PRs, statuses), read:org (org repos), nothing else. KageOps never needs delete_repo or admin:*.

Implications: Once a project is mapped, every successful task push happens immediately — there's no draft mode. If Aegis pushes to a wrong repo, revert via git push --force-with-lease from a checkout (KageOps does not run destructive remote ops). Rotate tokens at GitHub if you suspect leakage; the OS Keychain entry is replaced on next save.

Deployments

Azure environments, deploy targets, and history.

About this panel

What this does

One place to register your Azure environments — a subscription, resource group, region and (optionally) tenant + credential, given an operator-facing label. You enter these coordinates once: Cloud Burst uses an environment for ephemeral build-time compute (ACI), and Deployments uses it for persistent run-time hosting. No more typing the same subscription in two places.

How to use it:

  • Add Environment — register a subscription / resource group / region under a label like "Production AU".
  • Credentials — leave the credential ref blank to use DefaultAzureCredential (az-login / managed identity / env). Set a pointer only for a stored service principal.
  • Edit — resource group, region, tenant and credential are mutable. Label and subscription are the environment's identity; delete and recreate to change them.

Best practice: register each Azure subscription once here, then pick it from a dropdown wherever bursting or hosting needs it.

Implications: deleting an environment is blocked while a Cloud Burst pool still references it — repoint or delete that pool first. Register a deploy target below the registry to deploy a finished project to Azure (App Service or Static Web Apps); one-click teardown lands in a later release.

APO — Automatic Prompt Optimization

Review proposed prompt changes and roll back winners.

About this panel

What this does

APO mutates an agent's baseline prompt, scores each variant against a fixed bank of golden tasks using a cheap eval model, and proposes the best one for human review. Scope is intentionally narrow — only Scout, Herald, and Pixel — because those agents produce deterministic-quality output that's safe to evaluate offline.

How to use it:

  • Enable — set KAGEOPS_APO_ENABLED=1. The scheduler is off by default.
  • History & Proposals — every nightly run lands as proposed. KageOps never auto-applies — you click Accept or Reject.
  • Rollback — reverts the active prompt back to the previous version. Useful when an accepted change degrades real-world output.
  • Min delta — only proposals exceeding KAGEOPS_APO_MIN_DELTA over baseline are surfaced. Defaults to a meaningful improvement, not noise.

Best option: leave APO off until you've run ~20 projects. Without that history, golden-task scores can over-fit. Once enabled, accept proposals only after spot-checking 2-3 generated samples against the new prompt.

Implications: APO calls the mutator + eval models on a schedule — that's ongoing token spend even when you're not using the app. Default models are cheap (Haiku, gpt-4o-mini), but check Cost Intelligence regularly. To pause without losing history, unset KAGEOPS_APO_ENABLED; the proposals stay viewable here.
